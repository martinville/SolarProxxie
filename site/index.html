Local telemetry from an Inteless Wi-Fi dongle

SolarProxxie runs on an original ESP32. The dongle connects to the ESP32 access point, normal IPv4 traffic is forwarded to the home network, and supported telemetry packets are decoded for the local web interface, MQTT, and Home Assistant.

What the project does

Forwards traffic

The ESP32 provides the dongle with Wi-Fi, DHCP, DNS and an IPv4 route through the home network.

Observes telemetry

Bounded packet copies are decoded without changing the forwarded application payload.

Publishes readings

Mapped readings can be sent to an MQTT broker and represented as separate Home Assistant devices.

Handles multiple dongles

Up to eight IP-to-name/profile mappings are supported, with separate freshness and publication state.

Supports local fallback

Captured read-only cloud replies can keep supported telemetry flowing during a detected Internet outage.

Provides diagnostics

The interface reports network, parser, MQTT, memory, task and packet-capture status.

Monitoring scope

This firmware does not send inverter commands or Modbus writes. Packet formats were derived from captures and reference projects rather than a vendor API. Check readings against the actual inverter before using them for billing, safety decisions, or control automation.

How it works

The ESP32 sits on the network path used by the dongle and observes supported traffic.

→
2ESP32 gatewayDHCP · DNS · NAPT · parser
→
3Home networkVendor cloud and MQTT broker

Normal forwarding

  1. 1
    The ESP32 joins home Wi-Fi.

    Its station interface receives a DHCP or configured static address.

  2. 2
    The dongle joins the ESP32 AP.

    The ESP32 supplies an address, DNS and a default gateway.

  3. 3
    IPv4 traffic is forwarded.

    lwIP NAPT carries the dongle traffic through the station interface.

  4. 4
    Copies are decoded.

    Only bounded packet copies enter the stream and telemetry parser.

  5. 5
    Readings are published.

    Valid values become visible locally and can be sent to MQTT.

Operational controls

Cloud forwarding
Can be enabled or disabled per mapped dongle.
Data freshness
Marks a source unavailable after its configured timeout.
MQTT schedule
Supports change-driven publishing plus minimum and maximum intervals.
PCAP capture
Streams a bounded best-effort capture while Debug mode is active.
Offline fallback
Uses an ICMP signal and a strict vendor-host/TCP allowlist.
OTA
Writes an authenticated upload to the inactive application partition.

Data handling

Each source IP has its own values, inverter serial, last-valid time, freshness, change detection, and MQTT schedule. Display names, units and field suffixes are shared field settings. Unmapped sources may appear in diagnostics but are not published.

Changing a unit in the web interface changes the label only. It does not convert the numeric reading. Unsupported, malformed, fragmented, or out-of-order data can be missed by the bounded observer without intentionally blocking the original forwarded traffic.

Install firmware

Use a desktop Chromium browser and a USB data cable to write the complete image to an original ESP32.

Browser installer

Full USB installation

This installs the bootloader, partition table, initial OTA metadata, and SolarProxxie application. It is intended for a new installation or complete replacement.

This process erases existing ESP32 configuration.Saved Wi-Fi, administrator and MQTT settings on the selected board will be lost.

Web Serial is unavailable. Use current desktop Chrome or Edge, or follow the command-line instructions.

The installer requires an HTTPS page and permission to access the serial device.

The serial-device chooser is opened by the browser. This site cannot select a port or start flashing without your click.

Before connecting

  • Original dual-core ESP32 / ESP32-WROOM board with 4 MB flash
  • Desktop Google Chrome or Microsoft Edge
  • USB data cable, not a charge-only cable
  • Any serial monitor or IDE closed
  • Stable USB power during the installation

This build does not target ESP32-C3, C6, S2 or S3 boards.

Installation sequence

  1. 1
    Connect the ESP32 by USB.

    Wait for the operating system to detect its CP210x, CH340, FTDI, or other serial bridge.

  2. 2
    Select “Connect ESP32 and install”.

    Choose the serial device that appeared when the board was connected.

  3. 3
    Allow the full install to finish.

    Do not disconnect the cable or close the page while flash writing and verification are in progress.

  4. 4
    Use manual boot mode if required.

    If automatic connection fails, hold BOOT, tap EN/reset, start the connection, then release BOOT.

  5. 5
    Open initial setup.

    After restart, join SolarProxxie-Setup and browse to http://192.168.4.1.

  6. 6
    Connect the dongle.

    Use its normal provisioning method to join the protected SolarProxxie AP created during setup.

Updating an existing SolarProxxie device

Use the authenticated Firmware page on the ESP32 and upload only the application image. This path preserves configuration and uses the inactive OTA slot.

Command-line alternative

The complete source build can also be flashed from an ESP-IDF 5.4.2 terminal:

idf.py set-target esp32
idf.py build
idf.py -p COM5 flash monitor

Replace COM5 with the actual serial port. Detailed Windows and Linux instructions are in the repository's installation guide.

Security and network exposure

The firmware is intended for a trusted local network. It is not an Internet-facing management service.

The dongle web interface should be treated as unprotected

The tested dongle exposed a plain-HTTP interface without a visible login. It included Wi-Fi/network configuration, reboot and firmware-upload controls, with no visible authorization or CSRF mechanism. Destructive upload tests were not performed, so unknown server-side checks cannot be ruled out.

How SolarProxxie limits dongle UI exposure

The dongle is normally behind the ESP32 NAPT boundary with no inbound mapping from the home network. An authenticated SolarProxxie administrator can temporarily map ESP32:8080 to the selected dongle's port 80.

Off by default

No permanent inbound mapping is created.

15-minute limit

The mapping expires automatically.

Connected target only

The target must be a configured dongle currently on the ESP32 AP.

Automatic closure

Logout, disconnect, MAC change, upstream loss, NAPT shutdown or restart closes it.

This controls exposure; it does not add a password to the dongle.While port 8080 is enabled, any device able to reach that ESP32 address may be able to operate the dongle UI, including its firmware-upload function. Do not forward port 8080 through a router.

Implemented controls

  • WPA2-PSK for the normal dongle access point
  • Salted PBKDF2-HMAC-SHA256 administrator hashes
  • Random, peer-bound sessions with 30-minute idle expiry
  • HttpOnly and SameSite session cookies
  • Separate CSRF tokens for state-changing requests
  • Increasing login backoff
  • Authenticated SolarProxxie OTA endpoint
  • Content Security Policy and escaped UI content
  • Bounded request, socket, queue and parser resources

Known limitations

  • Management HTTP and MQTT are not encrypted
  • Default builds do not enable Secure Boot or flash encryption
  • Wi-Fi and MQTT credentials are recoverable from unencrypted NVS
  • Application OTA images are not publisher-authenticated without separate signed-image provisioning
  • AP clients are not mutually isolated
  • Telemetry authenticity is not cryptographically verified
  • PCAP files can contain private identifiers

About and sources

SolarProxxie combines ESP-IDF networking with packet layouts derived from captures and existing open-source references.

Project scope

The firmware is a local IPv4 gateway and telemetry monitor. It is not affiliated with Inteless, Sunsynk, Deye, E-Linter, or the inverter manufacturer. Product names remain the property of their owners.

Protocol behavior can change with dongle or inverter firmware. The repository keeps field evidence, capture notes, tests, and known limitations alongside the implementation.
